# 项目自动交接

## 目标与触发

让下一位 AI 仅凭项目中的 PROJECT_STATE.md 和仓库即可接续，保留完整需求、最新口径、实际停点与下一步。技能负责文档维护，不代表授权继续业务开发、提交代码、推送或执行平台操作。

对启用本技能的项目，开始开发、需求变化、重要阶段完成、准备暂停或结束时主动执行，无需用户重复说“更新文档”。普通答疑且没有新事实时不制造更新。技能不是后台进程或强制结束钩子；无法保证崩溃、强制终止或额度耗尽后写入，因此在重要阶段及时保存。

## 开始或接手

1. 阅读项目 AGENTS.md 和 PROJECT_STATE.md，包括需求来源、后续口径及原文附录。文件不存在时按用户授权创建；未知事项标明未知，不靠代码猜需求。
2. 核对分支、HEAD、git status --short 和任务相关 diff/源码。不把文档快照或 commit 标题当作功能验证。记录既有未提交文件，保留它们的内容与归属。
3. 如果有其他 AI 并行编辑，重新读取将修改的文档，只合并本轮事实，不覆盖较新的进度；记录并行工作边界。
4. 按用户当前任务继续；历史停工限制与后续明确授权冲突时标记已被替代。区分用户直接表达、旧交接转述、AI 建议及实现决策。

## 工作中与结束前自动保存

有新需求、可验证里程碑、失败/阻塞或用户要求暂停时及时更新。最终回复前执行一次差异核对与保存，内容包括：

- 更新时间、当前分支和检查时 HEAD。
- 需求台账：稳定 ID、来源、验收标准、状态和实现证据；新增需求补充，改变规则记录原因，不静默丢弃原始需求。
- 当前停点：已完成的具体行为、相关文件、未完成内容、阻塞和下一步第一件具体工作。
- 提交边界：哪些属于已有提交、哪些仍未提交、哪些是其他 AI 的改动。没有创建 commit 就明确说明；不要自动 git add/commit/push。
- 验证：实际运行的命令、目录、通过/失败/跳过结果与适用版本；没有运行就写未运行。离线测试、构建通过和真实平台验收分别记录。
- 决策与待定项：技术实现不自动升级为已确认业务规则，历史授权不扩展为新外部操作权限。
- 简短交接历史：本轮目标、变化、验证和下一步。更新当前状态，而不只在旧结论后堆积日志。

状态可用未开始、进行中、已实现待验证、已验证、阻塞；证据不足直接写待核实，不强行判定。只更新与本轮事实相关的状态，不能因写完文档就把业务需求标为完成。

## 文档与 Git 约束

- 沿用现有 PROJECT_STATE.md 结构和需求 ID；保留原文附录。原始需求只在用户要求修改原文时改动，后续确认另记覆盖口径。
- 单文件交接时，核心要求与最新口径写在正文；不能只留下失效的外部本地文件链接。不要主动复制整个聊天记录、终端日志或敏感资料。
- Cookie、密码、密钥、消息正文、真实地址等不进入交接文档。
- 无需重跑无关业务测试来更新文档；核实路径、链接、当前状态和 Markdown diff 即可。不能虚构未执行的验证。
- 用户已授权提交本轮代码时，把相关文档纳入同一提交，仅包含自己负责的改动；可写“随本轮提交”，不为记录文档自身哈希循环提交。
- 写入前重新读取文件，避免覆盖其他人的更新。写入后检查差异，确认需求原文仍在、最新状态不矛盾、没有意外删除。
- 无法写入时，在最终回复给出可粘贴的状态更新并说明未落盘；不要声称已完成自动交接。

## 输出

正常完成后在最终回复简短说明交接文档已更新，并链接文件；主体仍回答用户本轮任务。不要额外要求用户确认一次文档更新。

用户明确说“我要换 AI/暂停”时，先保存当前可确认的进度并停止新业务开发；提供下一位 AI 的最短接手提示：读取 AGENTS.md 与 PROJECT_STATE.md，核对 Git 后从记录的下一步继续。
